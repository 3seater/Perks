# Perks implementation plan

Updated September 19, 2026. This is the current product specification and initial source audit. Historical README implementation descriptions are not the accepted product model.

Latest direction: user explicitly chose to proceed with Cryptorefills after reviewing its no-KYC catalog claim. Continue integration without waiting for another provider search. Email remains acceptable; any verification requirement must stop the affected unpaid redemption. This does not establish that conditional API verification or post-payment reviews cannot occur. See CRYPTOREFILLS-INTEGRATION.md for current implementation and live read-only checks.

## Confirmed decisions

- Launch Pump tokens with creator fees assigned to Perks; no native cashback or holder-reward mode. No extra Perks launch or trading charge; network/protocol costs still apply.
- Optional creator initial buy with token estimate and explicit transaction costs. Users can buy and sell inside Perks.
- Each wallet earns from the actual creator fees generated by its own eligible buys/sells, including external frontends. Only trades generating attributable Perks receipts qualify. Holdings and hold time do not determine rewards; selling all tokens does not remove rewards.
- One SOL-denominated wallet reward balance, with per-token contribution history and estimated USD value. Final reward fraction is selected after cost measurement; historical entitlements retain their original rate.
- Confirmed trades may show pending earnings. Rewards become available only after matching fees are collected into the vault and reconciled.
- Main reserves separate from a limited platform-controlled fulfillment wallet. User has a treasury-owner wallet; obtain public address at configuration time. Do not request or commit seeds/private keys.
- Gift-card users browse/select inside Perks, enter email, review an exact SOL quote, then receive code/instructions and email. Merchant gift cards only initially. $5-$10 minimum is acceptable but not final.
- No surprise card service charge. Retained margin must cover fulfillment costs; products that cannot be funded sustainably must not be offered at a loss.
- SOL withdrawal shares the same available balance. User pays disclosed network fees. A tiny balance may be uneconomic to withdraw; show net amount before confirmation.
- Recipient KYC is a hard blocker. Operator personal KYC is acceptable. Email is acceptable. Cryptorefills is provisional because it can request recipient verification; pre-validation alone does not eliminate that possibility.
- Do not publicly launch with SOL-only rewards while gift cards remain unresolved. Continue development independently of provider approval.
- Planning allowance is approximately $100/month operating costs, with scope to be confirmed against actual service pricing. Do not rely on hypothetical token revenue or spend/subscribe without authorization. Earlier $100 fulfillment pilot is separate provisional planning context, not permission to transact.

## Implementation sequence and acceptance criteria

### 1. Trade reward ledger

Create immutable trade events identified by signature + instruction/event position + program. Record mint, venue, side, actual creator-fee lamports, beneficiary wallet and evidence used to identify it. Aggregators/bots can have intermediary signers: do not assume transaction fee payer is the trader. Unsupported ambiguous routes remain unresolved, never credited to a guessed wallet.

Add versioned reward policies, collection receipts, balanced journal entries, reservations and disbursements. Track pending, available, reserved and settled rewards per wallet/token. Use integer lamports and a documented rounding rule; retain dust without over-crediting. Replays must not credit twice.

Collection can aggregate multiple tokens and trades. Define deterministic allocation to proven pending liabilities with a collection watermark and unmatched-receipt bucket. A vault balance or matching total alone does not identify a token's fees. Fees above credited rewards become platform allocation, not a reason to increase previously promised entitlements.

Accept when direct curve/AMM buys and sells, external router fixtures, repeated events, sold-out wallets, ambiguous attribution and partial collections behave correctly. Holder snapshots can continue powering holder counts but must not affect reward claims.

### 2. Shared reservations and SOL withdrawal

Use one database-authoritative reservation mechanism for both card claims and withdrawals. Verify wallet authorization binds amount, destination, network, expiry and unique request. Never let concurrent actions spend the same funds. Separate transaction principal from actual network costs and reconcile unused fee allowance.

Persist signed payment/withdrawal transaction identity before broadcast. Reconcile uncertain outcomes before releasing reservations or creating replacements. Isolate signer access to workers with spending limits; ordinary web routes never hold treasury keys.

Accept when duplicate clicks, competing card/SOL requests, worker crashes, expired blockhashes and delayed confirmations cannot duplicate payment or manufacture spendable balances.

### 3. Provider-independent catalog and Cryptorefills prototype

Build normalized catalog records for country/currency/brand/product, denominations, restrictions, recipient fields and disclosure. Fetch read-only live catalog/quotes before paid testing. No automatic order creation for quote/testing purposes. Inspect actual response schemas and error semantics instead of assuming marketing examples are complete.

Create a provider adapter covering catalog, quote, validation, order creation, payment requirements, delivery lookup and reconciliation. Do not reuse Reloadly refund/status semantics. Never assume a local UUID makes provider requests idempotent.

Plan fiat-cost coverage at quote time: gift face value, provider premium, conversion/slippage/network costs and contingency must fit reward principal plus explicitly allocated platform subsidy. Pending rebates/referral commissions do not fund today's redemption. Add quote expiry and reject unsupported country/product combinations. Newsletter consent must default off; do not copy the documentation example's opt-in.

If KYC is indicated before purchase, stop without sending funds. Post-payment reviews still require reconciliation/refund before returning reserved funds. Because the user prohibits recipient KYC entirely, this fallback does not satisfy the launch requirement: obtain compatible terms or select another provider.

Accept when card selection is entirely in Perks, order states are clear, codes are private, errors do not lose reservations, and a separately authorized small paid pilot verifies actual delivery/costs. No provider currently passes the hard KYC gate.

### 4. Launch, trade and data

Recheck official Pump SDK/instruction/fee documents against installed versions before edits. Verify creator destination/modes, initial buy atomicity, slippage and rent/network costs. Add in-app buy/sell through supported routes with explicit limits and confirmation recovery.

Select indexing/RPC/streaming services only after measuring coverage, archival needs and pricing against the operating allowance. Existing full-block scanner is a correctness prototype, not a verified affordable scaling solution. Add restart/backfill reconciliation and gap detection. Feed freshness, market caps, holders and volume must use actual data and clearly identify unavailable/stale metrics.

### 5. Launch gates

- Compatible provider approved for the exact treasury-funded reward model with no recipient KYC.
- Measured sustainable reward fraction, not an arbitrary 80%/90% promise.
- Vault program compiled/reviewed/tested; signer custody, treasury address, reserve caps and recovery procedures configured.
- Database/Redis integration tests, protocol fixture tests, on-chain simulation and authorized funded pilot complete.
- Country/product restrictions and operator obligations reviewed for the actual business model; provider approval does not settle all platform obligations.
- Monitoring alerts on accounting mismatch, indexer gaps, liquidity shortfall and stuck payouts; automatic pause on mismatch.
- Budget and deployment plan settled; no reliance on projected coin earnings.
